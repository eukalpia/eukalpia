# Этап 3: приёмка (фото-режим с трассировкой)

Дата: 2026-10-12. Снимки: `app/test-results/shots/*-photo256.png`
(`node scripts/shots.mjs --size=320x180 --photo=256 <ракурс>`, по одному процессу на ракурс) и проверка отказа
`node scripts/shots.mjs --no-float`. Рендер в headless Chromium на SwiftShader (процессор вместо GPU),
поэтому кадры маленькие: на настоящей видеокарте 256 сэмплов в полном разрешении занимают секунды–минуты.

## Кадры после 256 сэмплов

PHOTO_ROWS

## Что проверено

- Отказ без `EXT_color_buffer_float`: сообщение «Photo mode needs floating-point render targets
  (EXT_color_buffer_float), which this GPU does not offer.», кнопка PHOTO возвращается, город продолжает рисоваться.
- Код трассировщика вынесен в отдельный чанк (`lazy-*.js`, ~170 КБ) и воркер BVH; основной чанк его не содержит.
- TESTS

## Найдено и исправлено при доводке

- Каждый сэмпл стоил полного растрового кадра (фасадные шейдеры, четыре каскада теней) только ради глубины
  для тумана и облаков: теперь растровый проход рисует глубину одним материалом, а тени во время трассировки
  не обновляются.
- Ожидание «обычный вид вернулся» в проверке отказа было короче одного кадра SwiftShader.

## Перенесено на следующие этапы

- Фокус по клику берётся из коллизий: по кроне дерева фокус уходит за неё.
- Шумоподавитель опирается на нормали и глубину растра, без отдельного буфера альбедо.
- Трассировщик печатает предупреждение об устаревании (`WebGLPathTracer` → WebGPU); WebGPU не цель по спецификации.
